## 0. 結論(TL;DR)

1. **勝ち筋は変わらない。ただし「市場に無い情報」を作れているかが全て。**
   Benter 型(オッズ抜きの基礎モデル → 市場オッズと合成 → 補正付き組合せ確率 → 期待値と
   Kelly)が今も唯一の実証済みアーキテクチャで、2026-09 時点で新しい ML 論文がこれを
   覆した例は見つからなかった [A]。現状の暫定 ΔR²≈0(基礎モデルが市場に何も足せていない)は、
   **設計の失敗ではなく特徴量の情報不足**として読むべき。
2. **今回いちばん大きい新発見: 「オッズの動き方」そのものが JRA で実証済みの強い情報。**
   JRA-VAN 全データ 2004–2023(約 89 万頭走)で、**締切前 5 分のオッズ下落は、同じ最終オッズの
   馬に比べて実回収率が大きく高い**(中央値オッズ約 25 倍において、10% の直前変動が最終オッズ 10% 差の約 14 倍の
   回収率差に相当)[A]。投票総額のほぼ半分が最終 5 分に入る [A]。
   → **オッズの時系列を記録すること自体がエッジの材料**であり、モデル改良より先に始める価値がある。
3. **無料でオッズ時系列の過去データが取れる可能性がある(keibaodds.com)。**
   実ブラウザで確認: 2023-09 / 2024-09 / 2025-09 のレースで**単勝 22〜23 時点の時系列**が残って
   いる(2022-09 は最終オッズ 1 時点のみ)。全券種のタブがあるが、3連単は上位数件しか表示されず
   全組合せ保持は未確認。利用規約で商用利用禁止。→ **個人研究用の検証データとして「直前
   オッズ変動」仮説を今すぐ過去データで検証できる**(§3.3)。
4. **有料データ(JRA-VAN)は使わない方針で問題ない。** 無料で埋められるもの(馬場含水率・
   クッション値、気象、血統、週次の追い切りタイム)と、**自前で前向きに収集するしかないもの
   (全券種の直前オッズ、馬体重発表後の変化)**を分けて計画する(§3)。
5. **同じ設計の OSS 先行事例が存在する**(`taito-station/paddock`、Rust、2,000 コミット超)。
   基礎モデル → Harville λ補正 → Benter 型対数合成 → EV 購入、評価は市場対比 pseudo-R²。
   ただし同リポが引用する補正パラメータの出典(「伊藤 2010」)は**実在を確認できなかった** [U]。
   参考にはなるが数値は借りない。
6. **コミュニティの「回収率 150%」はほぼ全てバックテスト・有料記事**。唯一の自己批判的な
   長期報告は「ワイド/三連複は荒れレース依存で安定しない」と結論 [C]。裁判で認定された勝者
   (回収率 103〜111%)も **薄く広く機械的に**張った人たちで、妙手ではない。期待値の現実的な
   上限は**数%〜10%**、これを越える主張は疑ってよい。

## 1. 論文レベルで実証されていること

### 1.1 モデル構造: Benter 型が今も唯一の「市場に勝った実録」

| 知見 | 証拠 | 本プロジェクトへの含意 |
|---|---|---|
| 条件付きロジット(レース内で確率を競わせる形)+ 基礎モデルと市場オッズの 2 段合成で香港市場に 5 年中 4 年勝った。市場超過情報は ΔR²≈0.018 と極小 | Benter 1994 [A]、Bolton & Chapman 1986 [B]、Chapman 1994 [B] | 設計はこのまま。「小さな ΔR² を組合せ馬券で増幅する」構造なので、単勝で ΔR² が出ないなら馬単でも勝てない |
| SVM 等の ML 分類器は条件付きロジットと同程度〜やや良い(英国・香港) | Lessmann, Sung & Johnson 2009/2010 (IJF, EJOR) [B] | GBDT で良い。モデル種類より特徴量と評価設計が支配的 |
| 2018–2026 の LightGBM / NN / Transformer 論文(韓国・ポーランド・豪英・日本の卒論等)は **市場対比の対数尤度(ΔR²)を報告していない**。精度や自前バックテスト ROI のみ | 各論文 [B]/[U] | 「ML で市場に勝った」と読める論文は無い。V2 の ΔR² ゲートは論文水準より厳しく、これは正しい |
| 着順全体を使う Plackett-Luce(exploded logit)は勝ち/負けの二値より 1 レースあたりの情報が多い。ただし競馬で二値 vs listwise を数値比較した論文は見つからず | Plackett 1975 / Bolton-Chapman 系譜 [B]、比較実験 [U] | V2 の「lambdarank は任意実験」は妥当。理論的裏付けはあるが、切り替えの根拠は自データの ΔR² で取る |

### 1.2 組合せ馬券の確率(Harville 補正)

- 素の Harville は本命馬の 2・3 着確率を系統的に過大評価する(Benter 論文が明記 [A]。Table 9/10 の Z=−4〜−8 という数値は paddock Issue #703 経由 [B])。
- 最も実用的な補正は **Lo & Bacon-Shone の discount model**(Lo, Bacon-Shone & Busche 1995,
  *Management Science* 41(6))[B]:

  ```
  馬単  P(i→j)   = p_i · p_j^λ₂ / Σ_{k≠i} p_k^λ₂
  三連単 P(i→j→k) = P(i→j) · p_k^λ₃ / Σ_{m≠i,j} p_m^λ₃        (λ=1 で Harville に一致)
  ```

  香港・米国での推定値は概ね **λ ∈ 0.7〜0.9** [B]。Henery / Stern モデルに近い精度で計算が軽い。
- 日本データでの λ 推定値として OSS(paddock)が「λ₂=0.81, λ₃=0.70(伊藤 2010, JRA 44,774R)」
  を引用しているが、**該当論文は見つからず、検索結果は照会数値をそのまま反響する典型的な誤引用
  パターンだった** [U]。同姓同年の実在論文(伊藤耕介 2010, 大阪商業大学紀要)は複勝的中率の技術
  分析モデルで別内容。→ **λ は自データで MLE 推定する**(V2 §2.6 の方針どおり)。数値は借りない。

### 1.3 JRA 市場の効率性: V2 の記述を訂正すべき点

- **本命-大穴バイアス(FLB)は JRA に存在する**(2004–2023, 大穴ほど実回収率が低い)[A: arXiv:2509.14645]。
  `STRATEGY_V2.md` §1.2 の「古典的な本命-大穴バイアスはほぼ無い」は出典不明の合成情報だったので
  **訂正対象**。含意: 極端な大穴を除外する V2 の D4 は正しく、むしろ重要。
- **締切に近づくほど市場は効率化する**(群集追随型の投票者比率が減る)[B: arXiv:2503.16470, JRA 2008 年 3,450R]。
- **最終 5 分のオッズ変動は、最終オッズに含まれない情報を持つ**(§0-2 の通り)[A]。
  論文の表現: 「最終価格は情報集約に十分ではない」。

### 1.4 評価・サイジング

- 市場対比 pseudo-R²(McFadden、対数尤度ベース)が「市場に無い情報」の標準指標 [A]。
- 期待値推定に誤差がある場合の Kelly は縮小が正解。実務標準は 1/4〜1/2 Kelly、
  閉形式の縮小係数は Baker & McHale 2013 (*Decision Analysis*) [B]。
- 三連単など裾の重い配当での ROI 信頼区間の競馬固有論文は無し。ブロック・ブートストラップで
  自前に作る(V2 §2.5 と同じ)。

### 1.5 「市場に無い情報」を持つとされる特徴量

論文で裏付けのあるもの(多くは実務者由来 [C]):
- **オッズ変動(直前 5 分)**: JRA で定量実証済 [A]。今回唯一の「日本の一次資料あり」。
- 区間タイム・ペース(上がり 3F、テン 3F、通過順から脚質): 実務者の一致した主張 [C]。
- 調教(追い切り): 生理学系の査読論文で運動能力との関連あり [B]、市場超過情報かは未検証。
- 馬場状態の細粒度(含水率・クッション値): 無料で公式が公開、論文的裏付けは無いが
  「馬場×脚質」交互作用の仮説は自然 [U]。

### 2.2 コミュニティの共通認識と、間違っている点

- **共通認識(正しい)**: netkeiba スクレイプ + LightGBM が事実上の標準。レース内ランキング
  問題として LambdaRank を使う議論も定着。全組合せ直前オッズは自前で発走直前に取るしかない
  (OSS で「過去の全組合せオッズ」を解決した例は無い)。
- **間違っている点**: (1) 人気・オッズをそのまま学習特徴に入れる(市場の複製になる)。
  (2) 回収率をバックテストで語る(直前オッズを使っていない、外れ値 2 発で決まる)。
  (3) 三連単から始める(検証に 10⁴〜10⁵ ベット必要)。
- **運用上の注意** [C, 未検証]: netkeiba は 2024-11 と 2025-10 にボット対策を強化したとの報告
  (単純な requests が遮断、挙動ベース検知で応答遅延)。本リポの chromiumoxide + キャッシュ +
  レート制限の設計は結果的に正しい。

## 4. 機械学習に詳しくない人向け: このシステムは何をするのか

### 4.1 一言で

**「オッズが示す市場の予想」より少しだけ正確な確率を作り、その差が出ている馬券だけを、
差の大きさに応じた金額で、たくさん買う。** 相手にしているのは馬ではなく「他の全投票者の
集合知(オッズ)」です。

### 4.2 データはどう確率になるか

```
[レースごとの表]                      [1 頭 1 行の特徴量]
  馬 / 騎手 / 斤量 / 前走 …   ──→   例: 前走の上がり 3F 順位、休養日数、
  過去の結果(着順・タイム)              騎手のこのコース勝率、クラス昇降 …
                                              │
                                              ▼
                            (A) 基礎モデル(LightGBM 等の決定木の集まり)
                                「この特徴の馬は過去どれくらい勝ったか」を学習
                                              │
                                              ▼  各馬のスコア → レース内で合計 100% に正規化
                            f = 基礎モデルの勝率   例: 18%, 12%, 9%, …
```

- **特徴量**とは「馬 1 頭を数字で表した行」。出馬表を見て人が気にすること(前走の内容、
  騎手、距離実績、馬場)を数値にしたものです。
- **重要な制約: ここにオッズや人気を入れない。** 入れると、モデルは「人気馬が勝つ」を学ぶだけで
  市場のコピーになり、市場より良い確率は作れません(§2.2 の失敗例)。
- **リーク(未来情報の混入)厳禁**: あるレースの予測には、そのレース開始時点で知り得た情報
  しか使えません。集計値(騎手勝率など)も「その日の前日まで」で計算します。バックテストで
  良く見えて実戦で負ける原因の第 1 位がこれです。

### 4.3 市場と合成する(ここが Benter の核心)

```
  市場の勝率 π = 1/オッズ を合計 100% に正規化(控除率を除く)
  基礎モデル f
        │
        ▼
  合成確率 c ∝ f^α × π^β      (α, β は過去データに最も当てはまる値を推定)
```

- 市場は非常に賢いので、通常 β が大きく α は小さい。**α > 0 なら「基礎モデルには市場に無い
  情報がある」**ということ。α≈0(現状の暫定結果 α=0.06)なら市場に何も足せていない。
- **ΔR² とは**: 「合成確率が勝ち馬を当てる説明力」から「市場だけの説明力」を引いた値。
  0 なら市場と同じ、正なら市場より良い。Benter は 0.018 で 5 年勝ちました。**ROI(回収率)
  より桁違いにブレが小さい**ので、まずこれを正にすることだけを目標にします。

### 4.4 なぜ単勝・ワイドから始めるのか

- 単勝は的中率が高い(数 %〜30%)ので、数百〜千レースで「勝てているか」が統計的に判定できます。
  三連単は的中率 1〜2% で配当の裾が重く、数万ベットまで判定できません。
- 控除率も単勝 20% < ワイド 22.5% < 馬単 25% < 三連単 27.5% で、単勝が最も有利です。
- エッジが単勝で確認できたら、**同じ確率を組合せ馬券に掛け算して増幅**します(Harville 補正付き)。
  逆に単勝で ΔR²≤0 なら組合せでも勝てません(算術)。

### 4.5 買い方(期待値と Kelly)

- 期待値 EV = 合成確率 × オッズ。**EV > 1.1 程度**のものだけ買う(1.0 ちょうどにすると
  「モデルが最も過大評価した馬」だけを拾う、いわゆる勝者の呪い)。
- 賭け金は Kelly 基準の 1/4。確率推定には誤差があるので、理論値の全額を張ると破産確率が上がります。
- 極端な大穴は除外(JRA でも本命-大穴バイアスが確認されている §1.3)。

### 4.6 「オッズの動き」をどう使うか(今回の新要素)

- 最終オッズが同じ 2 頭でも、**締切前 5 分で下がってきた馬の方が実際によく勝つ**ことが JRA の
  全データで示されています。これは「基礎モデル」の特徴量ではなく**市場側の情報**なので、
  上の合成式で π を「最終オッズ + 直前の下落幅で補正した市場確率」に置き換えて ΔR² を測ります。
- 現実の制約: 実際に買えるのは締切 1〜2 分前で、配当は最終オッズで決まる。自分が見た変動の
  「その後」は取れないので、この信号の一部は必ず目減りします(スリッページ)。paper-trading で
  実測する必要があります。

### 5.3 インターフェース(ターミナル完結、API は後出し)

```
   [収集デーモン]  ──→  SQLite  ──→  [予測ライブラリ(Rust crate)]  ──→  CLI (今)
   cron: 開催日朝に                     features / blend / harville /       keiba-api today
   レース発見、締切前に                  ev / kelly を 1 つの crate に        keiba-api race <id>
   1 分刻みオッズ取得                                                  └→  REST (後): serve が同 crate を呼ぶ
```

- 推薦ロジックを **CLI と HTTP の両方から呼べるライブラリ層**に置く。既存 `serve` コマンドが
  その受け口になるので、API 公開時に追加するのは認証とスキーマだけ。
- CLI の出力は「買い目・金額・EV・根拠(合成確率と市場確率の差)」の表と JSON の両方。
  paper-record はこの JSON をそのまま記録する。

### 5.4 順序(ゲートは V2 のまま)

1. **オッズ時系列アーカイブの常時稼働**(C2)。最初の週末から開始。
2. **2025 年ぶんの結果データ補完**(既存 `scrape-historical`。2025 が 0 レース)。
3. **C3 → C1 の検証**: 「最終オッズのみ」vs「最終オッズ + 直前変動」の ΔR² を 2023–2025 で測る。
   これが正なら、基礎モデルが弱くても「市場側だけで」エッジ候補が立つ。
4. 基礎モデル特徴量の追加(C7 ①→②)と GATE 1 の正式判定。
5. 単勝・ワイド用の paper-record/settle 拡張(V2 Task 2.x)→ GATE 2。

### 5.5 撤退条件(再掲・変更なし)

GATE 1 を 2 回失敗したら実弾はしない。C1 まで含めて ΔR²≤0 なら、無料データでは
市場超過情報が作れないという事実として受け入れる。オッズアーカイブだけは続ける(資産)。
